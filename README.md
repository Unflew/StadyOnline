# TeamOnline — Курсы

Курсы по макетам `Desktop.svg` / `Contune.svg` + личные кабинеты администратора, кураторов и учеников.
Flask + две базы данных: **MySQL** и **MongoDB**. Вёрстка рассчитана на экран 1440 px: контент 1120 px по центру.

## Запуск

```bash
docker compose up -d                  # MySQL 8 и MongoDB 7 на localhost (или используйте свои серверы)
pip install -r requirements.txt
python app.py                         # http://127.0.0.1:5000
```

При первом запуске приложение само создаёт таблицы и индексы и (на пустой базе) заполняет демо-данными.
Стереть всё в обеих базах и начать заново: `python db.py --force`.

**Чистый старт без демо-данных** (только администратор, остальное заводите сами):

```bash
python db.py --force --empty          # стирает обе базы и оставляет только администратора
# или при самом первом запуске на пустой базе:  NO_DEMO=1 python app.py
```

Логин и пароль администратора: `admin` / `admin123`, либо свои через `ADMIN_LOGIN` и `ADMIN_PASSWORD` (задайте до запуска команды выше).
Дальше: войдите, в «Пользователи» создайте куратора, в «Курсы» — курс и назначьте куратора, куратор добавит студентов и задания.

### Подключение (переменные окружения)

| Переменная | По умолчанию |
|------------|--------------|
| `MYSQL_HOST`, `MYSQL_PORT` | `127.0.0.1`, `3306` |
| `MYSQL_USER`, `MYSQL_PASSWORD` | `teamonline`, `teamonline` |
| `MYSQL_DATABASE` | `teamonline` (база должна существовать; в docker-compose создаётся сама) |
| `MONGO_URI`, `MONGO_DB` | `mongodb://127.0.0.1:27017`, `teamonline` |

Пароли по умолчанию — только для разработки.

### Что в какой базе

| MySQL (связи, целостность, join-ы) | MongoDB (журналы, дописываются потоком) |
|------------------------------------|-----------------------------------------|
| `curators`, `students`, `users` | `feed` — общая лента на главной |
| `courses`, `modules`, `enrollments` | `events` — журнал событий курса |
| `assignments`, `submissions` | `logins` — дни входов (серия «каждый день») |
|  | `achievements` — выданные достижения |

Связь между базами — по числовым id из MySQL (`user_id`, `course_id`). Транзакции работают только внутри MySQL:
запись в MongoDB идёт отдельной операцией. Удаляя курс или ученика, приложение само чистит их данные в MongoDB.
Даты в MySQL — настоящие `DATE`/`DATETIME`; слой `db.py` отдаёт их приложению строками ISO.

### Проверка без серверов

`python tests/smoke.py` — ~100 проверок прав доступа и сценариев. Драйверы там подменены заглушками из `tests/fakes`
(MySQL → SQLite, MongoDB → память), так что тест проверяет логику приложения, а не диалект настоящего MySQL.

Статусы курсов и «День N из M» считаются от сегодняшней даты. Чтобы увидеть день как на макете:

```bash
TODAY=2026-11-16 python app.py        # PowerShell: $env:TODAY="2026-11-16"; python app.py
```

## Личные кабинеты (вход по логину и паролю)

| Роль | Что доступно |
|------|--------------|
| **Администратор** | всё, что куратору, по всем курсам + создание курсов, назначение куратора, архив/удаление курса, раздел «Пользователи» (создать, удалить, сменить пароль) |
| **Куратор** | только свои курсы: редактирование курса и программы, студенты, **задания** (в т.ч. автопроверка), проверка работ и оценки, **статистика**: прогресс и активность учеников, сложность заданий |
| **Ученик** | свой кабинет: курсы и прогресс, задания и отправка ответов, **серия ежедневных входов** и достижения |

Демо-учётные записи (создаются при первом запуске, **смените пароли перед реальным использованием**):

- администратор: `admin` / `admin123` (можно задать `ADMIN_LOGIN`, `ADMIN_PASSWORD` до первого запуска)
- кураторы: `sidorov` (Python), `fomin` (SQL), `puchkov` (HTML и CSS), `kozlova` — пароль `curator123`
- ученики: например `sidorov.p`, `orlov.d` — пароль `student123` (логины всех — в «Пользователи»)

**Сложность задания** (0–100) считается по фактическим результатам: 45 % — недобор баллов, 25 % — доля неудачных попыток,
15 % — число попыток, 15 % — доля не выполнивших. Нужно минимум 3 проверенные попытки. Задание засчитано при ≥ 60 % баллов.

**Достижения:** первый вход, серии 3/7/14/30 дней подряд, 1/5/10 заданий, максимальный балл, выполнение после доработки, завершение курса.
Вход засчитывается при первом заходе на страницу кабинета за день.

Безопасность: пароли хранятся хешами, сессии подписаны (ключ — `SECRET_KEY` или файл `.secret_key`), CSRF-токен на всех изменяющих запросах,
ограничение попыток входа. За HTTPS задайте `COOKIE_SECURE=1`. Режим отладки: `FLASK_DEBUG=1` (только локально).
